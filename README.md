# Boss RPA · 投屏岗位筛选

在 Windows 上读取手机投屏的岗位详情，用本地 OCR 提取标题、工作地点和招聘者活跃时间。预览模式会筛选并翻页，自动模式还会匹配沟通按钮、核对结果并记录每次判断。

例如，武汉岗位的标题命中「招聘专员」会被跳过。发起沟通后，程序用「继续沟通」「已投递」等状态确认结果。页面仍在岗位详情但结果不明确时，程序会保存截图并继续下一条。

## 默认规则

| 项目 | 默认处理 |
| --- | --- |
| 工作地点为武汉 | 保留 |
| 工作地点为其他城市 | 跳过 |
| 岗位标题含经理助理、招聘专员、数据审核专员等排除词 | 跳过 |
| 今日活跃、在线、刚刚活跃、分钟/小时前回复、今日回复次数 | 保留 |
| 3 日内、7 日内活跃 | 保留 |
| 超过 7 天的状态，例如一个月内、两个月内、半年内活跃 | 跳过 |
| 只有回复率高、近期活跃，或文字识别不清 | 待确认，不点击 |
| 继续沟通、已沟通、已投递 | 跳过 |

城市只取职位标题下面的**工作地点**，不会根据公司名称判断。活跃时间只取招聘者信息区，不使用岗位发布时间，也不读取职位正文中的时间。

岗位方向按标题中的具体关键词判断。默认排除词见 `filters.py` 中的 `DEFAULT_EXCLUDED_TITLES`。

## Windows 使用方法

1. 安装 64 位 Python 3.10～3.12，推荐 3.12。把仓库克隆或解压到任意普通目录。
2. 双击 `install.bat`。脚本会在项目目录创建或复用 `.venv`，并安装 `requirements.txt` 里的依赖。
3. 打开手机投屏，进入一个岗位的**最顶部**。窗口完整放在主显示器内，保持手机竖屏；投屏需要支持左滑切换岗位、进入聊天后右键返回。
4. 双击 `start_preview.bat`：只显示“符合 / 跳过 / 待确认”和理由，会自动左滑，**不会点击沟通**。
5. 预览判断正常后，双击 `start_auto.bat`：自动点击通过筛选的岗位。

停止：控制台按 `Ctrl+C`，或者把鼠标移到主显示器左上角。运行时不要同时操作投屏。

在 IDE 中选用项目的 `.venv\Scripts\python.exe` 运行 `main.py`，默认进入预览。

## 修改筛选条件

用记事本打开 `config.json`，在 `filters` 中调整筛选：

```json
"filters": {
  "allowed_cities": ["武汉"],
  "max_active_days": 7
}
```

- 多个城市可以写 `["武汉", "长沙"]`，不要填区名或省名。
- 可添加 `"exclude_title_keywords": ["经理助理", "招聘专员"]` 自定义排除词。这会替换整套默认词，填 `[]` 可关闭标题过滤。省略该项会使用默认词。
- 活跃时间改为 `30`，表示接受标签时间范围在 30 天以内的招聘者；包含边界。
- 月、年按保守上界换算：一个月 31 天，一年 366 天。“两个月内活跃”按 62 天判断，“半年内活跃”按 183 天判断。
- “近期活跃”没有明确天数，默认待确认。没有读取到状态也不会直接通过。
- JSON 不支持注释，不要删除逗号或引号。

其他常用配置：

| 配置 | 用途 |
| --- | --- |
| `window_titles` | 投屏窗口标题包含的文字，按列表顺序查找；默认先找 `vivoScreen` |
| `limits.max_jobs` | 本轮最多检查岗位数，默认 100 |
| `limits.max_clicks` | 本轮最多点击沟通按钮的次数，含结果待确认的点击，默认 50 |
| `limits.max_consecutive_unknown` | 连续多少个岗位识别或按钮匹配不清就停止，默认 3 |
| `save_preview_screenshots` | 改为 `true` 时保存每个岗位的预览图；默认只保存待确认图 |
| `platform` | 默认 `boss`；也保留 `51job`、`zhilian` 的原按钮模板 |

本次按 BOSS 直聘截图验证；前程无忧、智联的筛选布局还没有实际截图验证，使用前先预览。

## 首屏区域和窗口边框

不用截取完整岗位介绍。程序只读取上方岗位信息和底部按钮，遇到标题换行、增加“昨日新发布”等内容，会通过“职位详情”文字确定招聘者区域的下边界。

如果投屏带很宽的工具栏、黑边或 Windows 标题栏，先修改 `window_region`，让截图覆盖手机画面：

```json
"window_region": [0.0, 0.0, 1.0, 1.0]
```

四项分别是窗口内的 `[左, 上, 右, 下]`，数值为 0～1 的比例。例如 `[0.0, 0.04, 0.94, 1.0]` 会去掉窗口上方 4% 和右侧 6%。此设置也决定点击和左滑的区域。

`ocr.header_region`、`ocr.footer_region` 使用同样格式，但比例相对于去掉边框后的手机画面。默认读取上方 8%～60% 和下方 82%～100%。找不到“职位详情”或地点时会停止或待确认，不会盲点。

## 先用已有截图测试

在项目目录打开 PowerShell：

```powershell
.\.venv\Scripts\python.exe -X utf8 main.py --image "D:\截图\岗位.jpg" --preview
.\.venv\Scripts\python.exe -X utf8 main.py --folder "D:\截图" --preview
```

截图测试不启动窗口控制，不操作鼠标。目录测试只检查该目录第一层的 PNG/JPG/JPEG/BMP。

## 记录和异常处理

每轮记录在 `logs/日期时间/`：

- `run.log`：运行过程和停止原因。
- `results.jsonl`：每个岗位的地点、状态原文、判断理由和按钮文字。
- `*_review.png`：现场模式下待确认岗位的截图。

点击前会重新识别当前岗位；只有 OCR 读到对应投递按钮，且按钮图片也匹配成功，才会点击。程序支持多种模板缩放，不会把“继续沟通”作为新岗位投递。

点击后看到同一岗位的按钮变成“继续沟通 / 已沟通 / 已投递”时，记录为已沟通。若仍在岗位详情页，但按钮或岗位识别对不上，就保存截图、记录“沟通结果待确认”并处理下一条。每次确认只检查页面，沟通按钮只点一次。无法回到岗位页时停止并保存 `logs/last_unconfirmed.png`。

左滑后会检查岗位是否变化，连续两次没有读到新岗位就停止。同一公司、同名岗位、同一招聘者、同地点的不同职位可能被视为同一岗位并停止。当前没有跨设备、跨平台的历史数据库。

如果一直提示“按钮图片未匹配”，在当前投屏大小下重新截取“立即沟通”文字及其背景，替换 `images/btn.png`，不要包含“继续沟通”。原按钮模板保留在 `images` 目录，其他两个平台也可以同样替换。

OCR 和图片识别已用所提供的截图测试。Windows 投屏的真实点击、右键返回、左滑行为需要在你的电脑上预览确认，窗口缩放或 UI 变化可能需要调整区域和模板。

## 测试和文件说明

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

| 文件 | 内容 |
| --- | --- |
| `main.py` | 启动参数、投屏控制、投递流程、运行记录 |
| `filters.py` | 地点提取、活跃时间解析、筛选规则 |
| `vision.py` | 本地 OCR、按钮图片匹配 |
| `config.json` | 城市、活跃时间、窗口和运行限制 |
| `tests/` | 筛选和流程异常测试，无需操作真实桌面 |

OCR 使用 [RapidOCR ONNX Runtime 1.4.4](https://pypi.org/project/rapidocr-onnxruntime/1.4.4/) 自带的模型，安装完成后截图识别在本机运行。
